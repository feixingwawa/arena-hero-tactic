# PRD：探索寻路优化

## 项目信息

- **Language**: 中文
- **Programming Language**: Python（现有 bot/ 模块架构）
- **Project Name**: arena_hero_tactic
- **原始需求复述**：当前 Arena Hero 的 Worker 探索存在两个核心问题：(1) **重复路程严重**——Worker 在 Core 附近 d=2~9 小范围内围绕曼哈顿环转圈，无记忆导致反复走过同一区域，线上实证 100+ tick 内 max d=9 全为 explore，无一次 to_resource/harvest；(2) **不向冠军信标（Beacon）导向**——Beacon 位置 (-56, -133) 距 Core 约 200 曼哈顿距离，但 Worker 只在 Core 周边绕行，不向该方向推进。Beacon 是游戏关键目标（持有者采集 1 点得 2 资源）。

## 产品定义

### Product Goals

1. **杜绝无效重复探索**：通过 chunk 级已探区域记忆，避免 Worker 在同一区域反复绕行，将有效探索覆盖范围从 d≤9 提升到 d≥20。
2. **实现 Beacon 导向推进**：当本地螺旋扫掠找不到资源时，自动切换探索方向朝向 Beacon，确保关键目标可被触及。
3. **保持低侵入性、高可测试性**：所有新逻辑封装在现有 `_spiral_state` / `SpiralState` 框架内，不改变 `decide()` → `command_workers()` 调用链，单测可 mock。

### User Stories

1. **As a** tactic bot developer, **I want** Worker 记录已探索过的 chunk，**so that** 它不会在同一曼哈顿环反复转圈，探索覆盖率随 tick 增长。
2. **As a** tactic bot developer, **I want** Worker 在本地搜索light时间段内找不到资源时自动切换探索目标为 Beacon 方向，**so that** Beacon 可被及时拾取/利用。
3. **As a** tactic bot developer, **I want** 多 Worker 可以分工（一个留守 Core 周边巡逻刷新，另一个推进 Beacon），**so that** 近程刷新发现和远程 Beacon 推进可并行。
4. **As a** tactic bot developer, **I want** 软回撤时优先切向 Beacon 方向而非退回 Core，**so that** 推进效率不因回撤而退化。

## 技术规范

### Requirements Pool

#### P0（Must have — 当前 sprint 必须完成）

| ID | 需求 | 验收标准 | 估算 |
|---|---|---|---|
| P0-1 | **朝 Beacon 导向的探索**：在 `_explore_spiral_step` 中，当 `st.stalled_ticks >= config.recall_stall_ticks` 且 `SpiralState.phase == 'local'` 且 `config.beacon_position` 有值，将 `st.phase` 切换为 `'beacon'`，生成朝向 Beacon 的路径目标。 | (a) 软回撤触发后若 Beacon 存在，explore 日志出现 `phase=beacon`；(b) Worker 曼哈顿距离逼近 Beacon 方向。 | 3d |
| P0-2 | **Chunk 级已探区域记忆**：在 `SpiralState` 或 `MemoryMap` 中记录已探索 chunk set；`_explore_spiral_step` 生成目标时跳过完全在已探 chunk 内的点；到达新 chunk 时记录。 | (a) 同一 chunk 被探索后，下次扇区目标跳过该 chunk；(b) explore 日志出现 `new_chunk` 标记。 | 2d |

#### P1（Should have — 显著提升）

| ID | 需求 | 验收标准 | 估算 |
|---|---|---|---|
| P1-1 | **多 Worker 分工**：当 `config.beacon_position` 有值时，指定 1 个 Worker 专门推进 Beacon（设置 `SpiralState.phase='beacon'` 且不 back to local），其余 Worker 保持 local 螺旋巡逻找资源刷新。 | (a) 日志出现 `dedicated_beacon` 标记；(b) Beacon Worker 持续远离 Core，local Worker 在 Core 周边。 | 2d |
| P1-2 | **软回撤优先切向 Beacon**：软回撤触发时，若 `config.beacon_position` 有值且目标不在 Beacon 方向，优先朝向 Beacon 方向生成下一目标点（而非默认 ring-1 向 Core 收缩）。 | (a) 软回撤日志出现 `recall_soft:beacon`；(b) Worker 不向 Core 方向后退。 | 1d |

#### P2（Nice to have — 锦上添花）

| ID | 需求 | 验收标准 | 估算 |
|---|---|---|---|
| P2-1 | **Beacon 位置实时追踪**：`TacticConfig.beacon_position` 在每个 tick 由 `decide()` 从 `turn.beacon.position` 更新；若 Beacon 被拾取（status=GROUND 或 CARRIED 或消失），清除或标记。 | (a) 每 tick beacon_position 与 turn 同步；(b) 被拾取后 Worker 自动停止推进。 | 0.5d |
| P2-2 | **Beacon 路径障碍规避记录**：在 `MemoryMap` 中扩展障碍记录为 `ObstacleCache`（含 tick），朝 Beacon 推进时遇到障碍标记并加入局部避障候选集。 | (a) 推进路径中的障碍在日志可见；(b) 不因同一障碍反复卡 stall。 | 1d |

### UI Design Draft

本 PRD 不涉及 UI 层改动。所有改动集中在：

1. **`bot/config.py`**：`TacticConfig` 新增 `beacon_position: Optional[Position] = None` 字段。
2. **`bot/memory.py`**：`MemoryMap` 新增 `explored_chunks: set[tuple[int, int]]` 和相应记录方法。
3. **`bot/economy.py`**：`SpiralState` 新增 `phase: str = "local"`（已存在）、`explored_chunks` 引用、Beacon 导向目标生成逻辑。
4. **`bot/strategy.py`**：`decide()` 每 tick 更新 `config.beacon_position`（若 turn 有 beacon）。

### Open Questions

1. **Beacon 被敌方拾取后的行为**：若 Beacon 被敌方 Worker 拾取（CARRIED by enemy），当前 Worker 是否应追击该敌方单位而非仅朝原 Beacon 位置推进？需要确认 Beacon carrier 是否对敌方可见，以及追击策略是否在本 PRD 范围内。
2. **Chunk 记忆的有效期**：已探 chunk 是否需要在特定 tick 后过期（考虑游戏地图可能动态变化），还是整局永久记录？当前建议永久记录，但需确认游戏规则。
